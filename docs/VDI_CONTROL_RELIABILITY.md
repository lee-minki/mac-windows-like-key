# VDI Control 매핑 불일치 — 2026-11-26

추적: [이슈 #7](https://github.com/lee-minki/mac-windows-like-key/issues/7). 로컬 한글 조합 누락 [이슈 #6](https://github.com/lee-minki/mac-windows-like-key/issues/6)과 구분한다.

## 현재 상태

설치본은 정식 **1.8.6 / build 29**다. 16:08:52에 대상 외장 키보드의 Control 적용값을 임시 복구하고 읽기 검증했다. 이후 사용자가 “제대로 컨트롤로 동작중”, “복구되었어”라고 답해 실제 복구를 확인했다. 재발 방지 소스 수정은 자동 검사와 Debug 빌드를 통과했지만 새 앱 배포·설치는 아직 하지 않았다. 이모지 창 증상의 정확한 원인은 미확정이다.

## 확인한 사실

- 사용자는 VDI 단축키 실패, Control 입력 시 이모지 창 및 Windows 시작 메뉴가 열리는 현상을 보고했다. 물리 키보드를 직접 명명한 답은 없으나, 외장 키보드만 복구한 뒤 실제 복구를 확인했다.
- 외장 Gaming Keyboard의 저장된 Mac 목표는 `Ctrl → Command`, VDI 목표는 `Ctrl → Ctrl`이다. 저장 프로필은 설치 전 백업과 동일하다.
- Horizon VDI 컨텍스트에서 외장 키보드의 2개 HID 서비스에 `Control → Command`가 남아 있었다. `Option → Command`, `Command → Option`, `Right Command → F16`은 VDI 목표대로였다.
- 프로필 변환과 HID 변환이 동일 키 항목을 생략한다. 이전 `Control → Command` 값이 있는 상태에서 직접 VDI 시작 및 Mac → VDI 전환 시 이전 값이 남는 것을 가짜 백엔드로 재현했다. 해당 로직은 1.8.5에도 존재하며 이전 값의 최초 작성자는 확인하지 못했다.
- 내장 프로필의 물리 Control → Windows는 저장 배열 자체의 동작이다. 내장 프로필을 외장 문제와 함께 바꾸지 않았다.

## 임시 복구 및 되돌리기

Horizon 포커스, 보조키 미누름, 대상 VID:PID와 예상 VDI 값의 일치를 확인한 다음, 외장 키보드의 **Control 소스 하나만 Control → Control**로 바꿨다. 두 서비스 모두 전체 결과를 다시 읽어 다른 항목이 그대로임을 검증했다. 다른 키보드·저장 프로필·Horizon 설정·개인정보 권한은 변경하지 않았다.

로컬 증거는 무시된 `build/vdi-control-20261126/repair-applied.json`에 변경 전/후 값을 보관한다. 이 조치는 실행 중 HID 값만 복구하며, 재연결·다른 도구의 재설정 뒤까지 보장하지 않는다. 되돌릴 경우 최신 값을 먼저 읽고 대상 Control이 복구값과 같은 경우에만 그 소스를 보관한 이전 값으로 돌린다. 전체 HID 초기화나 과거의 전체 스냅샷 덮어쓰기는 하지 않는다. 이전 값으로 되돌리면 이 증상이 다시 나타날 수 있다.

## 재발 방지 수정 범위

- 두 컨텍스트 중 한쪽에서 재배치하는 키는 다른 컨텍스트의 동일 키 목표도 명시적으로 적용한다.
- 양쪽에서 항상 그대로 두는 키는 관리 대상에 넣지 않는다. `한/영 전환만` 프로필과 외부 도구의 관련 없는 매핑을 보존한다.
- 기존 소유권 기록으로 엔진 정지 시 원래 값 복원과 이후 외부 변경 보존을 유지한다.
- F16 릴레이, 내장 배열, 다른 키보드 바인딩은 변경하지 않는다.

## 검증 구분

- 수정 전 회귀 검사: 이전 `Ctrl → Command`가 있는 직접 VDI 시작 및 Mac → VDI 이동 2건에서 실패.
- 수정 후 회귀 검사: 36개 기대값 통과. 전체 19개 smoke 및 버전·릴리스 workflow·reset 키 검사 3개 통과.
- Debug 앱 빌드 성공. 시스템 기본 Xcode 경로는 바꾸지 않고 해당 빌드에만 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`를 지정했다. 이 빌드 결과물을 설치·실행하지 않았다.
- 임시 복구: 두 HID 서비스 읽기 검증 성공, 16:13에도 같은 값 유지. 사용자에게 Ctrl 단독 및 Ctrl+C/Ctrl+V 확인을 요청했고 “복구되었어” 응답을 받았다. 개별 조합별 추가 기록은 없다.
- 수정 앱 배포·설치, Mac↔VDI 왕복·재연결·재시작, 내장 배열과 한영 전환의 추가 실사용은 아직 확인 전이다. 이번 Ctrl 복구로 로컬 한글 조합이나 이모지 증상의 원인을 확정하지 않는다.
