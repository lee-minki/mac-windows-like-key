# WinMacKey 다음 PR의 Council 리뷰

다음 WinMacKey PR 리뷰에서 `t3dotgg/tstack`의 `council`만 시험한다. `full-send`를 포함한 다른 tstack 스킬은 이 절차에 포함하지 않는다.

## 설치와 출처

- 원본: [council/SKILL.md](https://github.com/t3dotgg/tstack/blob/1085050f3baed1ac724caa4a8166145fb2ac88af/skills/council/SKILL.md)
- 고정 커밋: `1085050f3baed1ac724caa4a8166145fb2ac88af` (2026-10-28 확인)
- 설치 위치: `~/.codex/skills/council/SKILL.md`. 원본 스킬은 수정하지 않고, 프로젝트 조건은 이 문서와 `AGENTS.md`에 둔다.
- 새 환경에서 단독 설치하려면 Codex의 `skill-installer`에 위 저장소의 `skills/council`과 고정 커밋을 지정한다. 설치 후 다음 대화 턴부터 사용할 수 있다.

스킬 설치만으로 세 제공사의 모델 호출이 준비되지는 않는다. Codex 기본 서브에이전트는 현재 OpenAI 모델만 제공하므로, Claude·Gemini 등 다른 제공사는 해당 모델을 실행할 수 있는 CLI 또는 하네스가 필요하다. 실행 전 각 제공사의 인증, 사용 가능한 정확한 모델 ID, 높은 추론 수준 지원을 확인한다. CLI 파일이 있다는 사실만으로 호출 가능하다고 판정하지 않는다.

## 실행 순서

1. 대상 PR의 URL, base/head 커밋과 작업 폴더를 확인한다. 로컬 미커밋 변경은 PR diff와 구분하고 기존 작업을 보존한다. 알려진 문제와 기존 리뷰 코멘트를 먼저 처리하되, 수정은 사용자가 허용한 PR 범위로 제한한다.
2. 관련 검사를 실행하고 결과와 미검증 항목을 정리한다. 코드 변경이 있으면 `bash scripts/run-tests.sh`와 필요한 빌드·수동 확인을 수행한다.
3. 서로 다른 제공사 세 곳에서 강한 모델을 하나씩 선택해 높은 추론 수준으로 병렬 리뷰를 요청한다. 사용자 지정 멤버가 있으면 우선한다. 제공사 하나라도 사용할 수 없으면 원인을 보고하고 `partial`로 남긴다. 같은 제공사의 모델 세 개로 대체하거나 합의 완료로 표시하지 않는다.
4. 세 리뷰어에게 같은 커밋의 diff, 관련 문서와 검증 근거를 주고 읽기 전용으로 작업하게 한다. 각자 결함의 파일·라인·재현 조건, 권고와 10점 만점 점수를 요청한다.
5. 근거 있는 지적을 검토해 필요한 수정과 검사를 수행한 후 세 리뷰어에게 새 리뷰를 요청한다. 전체 리뷰 한 번을 한 라운드로 센다. 세 리뷰어가 모두 수용할 때 완료하며, 점수의 고정 합격선은 두지 않는다. 미해결 이견은 그대로 기록하고 범위를 확대하지 않는다.
6. PR이 있으면 본문의 `Council review` 절에 라운드와 모델별 점수를 기록한다. 모델·하네스 표기가 있다면 그 앞에 둔다. 점수가 없으면 `no score`로 적는다. PR이 없으면 최종 답변에 기록한다. 이 시험에서 GitHub 리뷰 댓글을 게시하지 않는다.

실행 요청 예시:

```text
council로 이 WinMacKey PR을 리뷰해줘: <PR URL>
docs/COUNCIL_REVIEW.md를 따르고, 3개 제공사 접근 가능 여부를 먼저 확인해.
로컬 Mac, Horizon, Windows App과 키보드별 프로필의 검증 근거를 구분해.
```

## WinMacKey 검토 조건

- 로컬 macOS의 입력소스 전환과 Horizon의 `F16 → Right Alt` 중계를 구분해서 검토한다. Windows App의 별도 개선 후보는 v1.8.5 릴리스 범위에 포함되지 않으며, 해당 후보의 변경·검증 결과를 이번 PR에 섞지 않는다. F18을 현재 중계 키로 취급하지 않는다.
- 내장·외장 키보드별 프로필과 포커스 전환, 키 누름/뗌, 엔진 정지·복구를 확인한다. 관련 수동 검증은 [MANUAL_TEST_PLAN.md](MANUAL_TEST_PLAN.md)를 따른다.
- 빌드·합성 이벤트 검사와 실제 키보드·원격 Windows 검증을 구분한다. 모델 세 곳의 합의가 있어도 실제 동작 근거가 없으면 해당 항목은 미검증으로 남긴다.
- 사용자 설정의 기준은 [SETUP_GUIDE.md](SETUP_GUIDE.md)와 [VDI_SETUP.md](VDI_SETUP.md)다. 매핑 변경에는 기존 복구 경로와 되돌리는 방법도 확인한다.
- 이 리뷰 절차는 자동 커밋·푸시·머지, 설치 앱 교체, macOS 보안·개인정보 설정 변경을 허용하지 않는다.

아래 표의 모델명은 실제 사용한 이름과 ID로 채운다. 실행 전에는 결과를 만들지 않는다.

```markdown
| <제공사 B / 모델 ID> | <실제 점수 또는 no score> |
| <제공사 C / 모델 ID> | <실제 점수 또는 no score> |

검증: <실행한 검사와 결과>
미검증: <실제 키보드·VDI 등 남은 확인>
미해결 이견: <있으면 근거와 함께 기록>
```
